# ADR-001: Static evidence site and isolated console probes

Status: Accepted for research preview, 2026-11-07.

## Context

Official retail Developer Mode applies to Series X|S. UWP runs in a constrained sandbox. Shared Windows API names do not imply console implementation. Current Windows ML targets Windows PCs and the Windows App SDK; it is distinct from the legacy Windows.AI.MachineLearning WinRT API. No console is attached to this development environment.

## Decision

Generate ten static HTML routes with strict TypeScript. Keep browser JavaScript limited to search, copy and navigation. Validate registry data with Zod during builds. Require provenance, raw measurements and correctness before publishing validated records. Keep EXP-001 unverified and measurements empty. Use the legacy WinRT CPU API as a candidate probe with an explicit runtime availability gate, not as an established execution path. Keep GPU, bundled ONNX Runtime and transformers separate hypotheses.

The UWP integration example is manually added to an official Blank App template on Windows. It is not a compiled or deployable Xbox package in this preview. Website CI and Linux host tests cannot establish console compatibility.

## Alternatives

Vinext/React would add a server or hydration overhead to a static documentation product. Static HTML generation provides direct routes and a deployable directory without a framework service. Current Windows ML, desktop Python and GDK are not substitutes for Xbox UWP validation. Custom shaders would enlarge the operator-validation scope before a baseline exists.

## Consequences

No benchmark charts until actual reviewed measurements exist. No account, telemetry or backend is needed. Manual Windows compilation, console execution and independent review remain release gates. A future ADR is required to adopt a different runtime.
