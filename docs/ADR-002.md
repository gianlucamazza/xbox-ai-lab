# ADR-002 — Linux-first native UWP build and packaging

Status: Accepted architecture; Xbox AI Lab integration pending. 7 November 2026.

## Correction to ADR-001

A Windows host is not a necessary prerequisite for UWP compilation, packaging, signing or deployment. Reuse the existing uwp-crossbuild and openappx projects. Their source and upstream CI were reviewed; no full SDK build or console run was performed by this lab during the review.

## Decision

Use a native C++/WinRT x64 application, with the visual tree built in code and no .xaml files. uwp-crossbuild produces executable, generated .winmd and package layout; openappx validates, packs, signs, inspects and talks to authenticated Windows Device Portal. Port the semantics of examples/Probe.cs to native code in issue #3. Retain the C# example and Windows/Visual Studio as an optional reference/comparison path.

Pin uwp-crossbuild to `e692f28ea613bba9bc08715ef111ad48992bf6a3` and openappx source to `ceaf535424c23db03d7c46e28e36c01b528ad237` (pyproject version 0.7.0). Do not confuse the launch-fix minimum openappx 0.6.3 with the selected reviewed pin. Pin SDK/CRT, LLVM, Wine and cppwinrt/header versions in the integration record. Some official SDK utilities run under Wine; this is not a Windows-free binary toolchain or a Microsoft-endorsed Linux SDK distribution. Deployment still uses official developer interfaces; the community host implementation is not an expanded console API entitlement.

## Evidence levels

1. Source reviewed: native compilation and .vcxproj subset in uwp-crossbuild, pack/sign/inspect/deploy in openappx.
2. Upstream CI: uwp-crossbuild scripts passed with full-build skipped; openappx Python 3.10–3.14 jobs passed at a distinct recorded revision.
3. Upstream reported hardware: one Series S (OS 26100.8866), visible launch and a GGUF model load described in source documentation. These descriptions are not a new lab capture and do not establish the retail-versus-managed hardware provenance required by our protocol.
4. Lab reproduction: native probe, full SDK build, deployment and EXP-001 numerical evidence remain pending. API presence, import, inference correctness, GPU execution and generation are separate gates.

## Constraints and consequences

- No direct .csproj/C# compilation and no .xaml compiler in the reviewed path. Reusing Probe.cs unchanged is not an implementation.
- The .vcxproj evaluator intentionally refuses unsupported MSBuild constructs. Native NuGet DLL availability does not prove console runtime support.
- Split fast source/script tests from an explicit SDK-bearing build job. Green script CI is not a compiled UWP application; follow upstream Wine/MSXML and SDK-acquisition requirements.
- Keep signing keys, console credentials and trusted certificate fingerprints outside source. Publisher and certificate subject must match.
- Use direct openappx deployment with certificate pinning. The reviewed run-on-device.sh hardcodes --insecure; do not copy that helper unchanged into the preferred path.
- Capture PE architecture/AppContainer flags, activation metadata, model checksum, package inspection and hashes before deployment. Console tests remain required even if all host gates pass.
- No changes to EXP-001 status or benchmark measurements follow from this ADR.
